# Foundation audit — 2026-11-12

Scope: the existing 0.3.0 repository plus unfinished local validation and demo
work. The changes are consolidated in 0.4.0. This is an engineering review,
not an independent security certification.

| Finding | Resolution / regression coverage |
| --- | --- |
| Schema constraints could be dropped; port metadata was not strict | Reject unsupported keys and malformed values; panel and foundation tests. |
| Local-origin exception admitted non-HTTP schemes; ambiguous endpoint forms | Shared origin validation and explicit endpoint rules; malformed URL tests. |
| Runtime argument checks rejected unknown keys while exported JSON Schema allowed them | Emit `additionalProperties: false` recursively; MCP/validator agreement test. |
| User-controlled property names could alter plain-object prototypes | Reject reserved keys before copying; prototype-sensitive input tests. |
| Trace creation could use a foreign port or an unvalidated panel | Normalize the panel and resolve its port by ID; impostor and binding tests. |
| Password inference and write-only array-item redaction were missing | Mark password fields and redact at every schema node; trace secrecy tests. |
| Trace dates/result digests could be malformed | Validate real UTC timestamps and SHA-256 representation; malformed trace tests. |
| Any JSON-LD Action was treated as a read | Restrict structured inference to SearchAction; mutation-action tests. |
| Candidate IDs could collide; commented/scripted forms were treated as real | Collision-safe IDs and static-source filtering; inference regressions. |
| Bad inference could still pass at a low score threshold | Hard-fail mismatched origins and weakened effects/confirmations; scoring tests. |
| A real field named description vanished from scoring | Strip schema annotations only; structural comparison test. |
| Invalid ground truth or empty capture could produce misleading passes | Validate expected panels first and always fail errored captures; corpus tests. |
| Private-IP heuristic overmatched domain names and missed mapped IPv6 | Literal-aware matching with IPv4-mapped handling; URL screening tests. |
| Truncated/SPA-fallback bodies could masquerade as discovery evidence | Reject oversize bodies, require JSON objects/plain text for markers; probe tests. |
| Unknown command flags and extra arguments were silently accepted | Validate per-command arity/flags; CLI misuse tests. |
| Local demo had no npm command and a broken test cleanup variable | Demo script plus real loopback integration and CLI smoke tests. |
| README conflated declarations, approval enforcement and signed evidence | Rewritten README, API/integration guides, safety model and honest roadmap. |

Validation runs use Node 24.16+. The unit/CLI suite and offline walkthrough run
without network access. The separate integration suite starts a real loopback
server, probes its published panel, infers the page, checks a real read response,
and verifies writes are refused. `npm run check` runs both suites and the tour;
GitHub CI additionally checks package contents with `npm pack --dry-run`.

Known boundaries remain explicit: no executor, authentication/approval service,
MCP transport, result validator, browser SDK or WebMCP adapter. DNS rebinding
requires external network policy. Static inference is limited; three synthetic
fixtures do not prove real-site accuracy. The license remains unresolved and
npm publication stays disabled.

Compatibility: normalized defaults and digests change from 0.3.0. Preserve old
panels with old traces; see CHANGELOG.md before comparing revisions.

## Follow-up: use readiness, 0.4.1

The final pass reproduced four false-positive verification cases: recomputed
traces with a malformed result digest, numeric outcome code, unknown record field
or wrong argument type. The verifier now enforces the record shape and, when a
panel is supplied, argument types/required fields and secret-redaction markers.
Tests also cover accessor-bearing inputs without invoking their getters.

Explicit zero/null/false inference options no longer select silent defaults.
The new consumer example performs one actual application-function read against
fake data and checks the result. A packed-install smoke check runs in CI, which
also uses current SHA-pinned actions and the exact supported Node version.

The remaining adoption blockers are product boundaries, not failing tests:
license selection, an owned npm identity, and a real client adapter with scoped
application access. See DISTRIBUTION.md. None is claimed to be released already.


## Follow-up: standalone distribution, 0.5.0

The first useful client integration no longer depends on owning an application.
Five fixed offline tools are callable through the official SDK's stdio server.
An SDK client exercises discovery, all handlers, rejection cases and shutdown.
Compiled panel ports are not registered as executable tools.

A clean package install found that entry-point detection compared a real module
path with npm's symlink path, silently doing nothing when launched through the
installed command. Resolve the entry-point symlink before comparison and test
both `--version` and real MCP calls through the installed command.

Documentation now separates the standalone toolkit from future partner-owned
application execution. Public reuse still awaits an explicit license decision.

Connected CI passed 107 unit/CLI tests and four HTTP integration tests, plus the
official SDK client smoke check and a clean installed-command MCP check. The
resolved dependency graph is committed with npm integrity hashes; CI uses
`npm ci --ignore-scripts`. Local unit checks also pass. No external deployment,
registry listing or model-host UI compatibility result is implied by these tests.
