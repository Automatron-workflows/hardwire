# Hardwire 0.9.0

Agentic actions. Without the clicks.

This release makes the inspection toolkit easier to distribute. The desktop
bundle includes the server and locked runtime dependencies. Its five tools infer
and validate contracts from supplied HTML and JSON; they do not log in, make
payments or execute inferred operations.

[Try the three scenes](https://automatron-workflows.github.io/hardwire/experiment.html)
· [Desktop installation](https://github.com/Automatron-workflows/hardwire/blob/v0.9.0/docs/DESKTOP-BUNDLE.md)

## One concrete experiment

With Node 22 or newer:

```sh
npx --yes --ignore-scripts --package=https://github.com/Automatron-workflows/hardwire/releases/download/v0.9.0/hardwire-0.9.0.tgz hardwire-form
```

The bundled settings form produces a candidate contract. Boolean `false` passes;
string `"false"` is rejected. Add `--json` to inspect the generated MCP tool.
Replace `hardwire-form` with `hardwire-experiment` to run all three local scenes.

## Downloads and verification

The release contains `.tgz` and `.mcpb` packages, matching registry `server.json`
and `SHA256SUMS`. The release workflow downloads and verifies the uploaded assets,
installs the tarball in a fresh project, and extracts and tests the bundle through
actual MCP calls before publication. No package installation is needed to run
the extracted bundle; its host still needs a compatible Node runtime.

The MCP Registry publishing workflow uses the GitHub bundle and repository OIDC
identity, so it does not need an npm account or token. Registry publication is a
separate operation after this release. Native desktop host setup remains
unverified. npm publication still needs a verified owner and package scope.

The README now leads with one reproducible task, and the website includes social
preview metadata using the existing artwork. The approved visual journey is
preserved. All account and payment examples remain local fixtures.
