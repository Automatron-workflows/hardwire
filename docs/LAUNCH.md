# Hardwire launch

## The invitation

Run the three actions from the demo. Change an input. Watch validation reject it
before local state changes. Share the result and the first thing that confused you.

The audience is developers building agents, MCP integrations and application
tooling. The film shows the idea; the experiment demonstrates checked local
handlers. Keep both links together and describe the experimental boundaries.

## Fourteen day sequence

| Days | Work | Evidence |
| --- | --- | --- |
| 1 to 3 | Cinematic experiment, versioned GitHub package, community and setup guides | Fresh installation and one complete local run |
| 4 to 6 | Invite 20 relevant builders personally and help unblock their first attempt | Five independently completed experiments |
| 7 to 10 | Publish a short demonstration and reproducible technical walkthrough | Useful reports, questions and outside examples |
| 11 to 14 | Fix reported friction and ship a follow up based on evidence | Returning users and reviewed contributions |

The npm and MCP Registry path requires an authenticated publisher and verified
scope ownership. A package downloaded from the GitHub release already provides
a usable distribution route. Two independent desktop client evaluations remain
a separate evidence goal; protocol tests alone do not satisfy it.

Track voluntary reports in GitHub. Record first run completion, return use,
contributions and repository traffic separately. No tracking is added to the
demo. Ten independent users, three returning users and three outside
contributions are working goals. One thousand stars is a stretch target, not a
forecast or a claim of adoption.

## Draft public post

I built Hardwire to make application actions explicit before an agent uses them.

The demo shows three familiar tasks: sign in, pay an invoice and change a setting.
You can now run all three locally, change the inputs and see what gets blocked.

No app or API key needed. The examples use local fixtures, so no accounts connect
and no money moves. The toolkit validates the contract; your app still owns its
authentication, approvals and handlers.

Try it: https://automatron-workflows.github.io/hardwire/experiment.html
Code: https://github.com/Automatron-workflows/hardwire

If you are building agents, I would like to hear where the first experiment
breaks or becomes confusing. There are scoped contribution tasks on GitHub too.
